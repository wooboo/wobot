# Wobot

Firmware and shared control logic for the TSCINBUNY ZYC0076 mecanum robot.

Arduino Alvik has a separate [MicroPython Wi-Fi controller](firmware/alvik-controller/README.md).
It uses the same Pocket ELRS Wi-Fi Joystick transport and Alvik's motor API.
The firmware and hardware instructions below apply to the original ZYC0076.

Ustalenia dotyczące sprzętu i transportu: [docs/pocket-setup.md](docs/pocket-setup.md).

## Intended data path

```text
RadioMaster Pocket ELRS Wi-Fi Joystick (UDP/11000)
  -> ESP32-S3 N16R8 (Rust, networking and supervision)
  -> framed UART protocol (115200 baud)
  -> ATmega328P/UNO (motor watchdog and PWM)
  -> 74HC595 + motor bridges
```

The motor controller must stop independently when commands expire. An `ARM`
channel and a valid checksum are required before non-zero motor output is
accepted.

## Hardware notes recovered from the manufacturer's ZYC0076 sources

- UNO-compatible MCU: ATmega328P
- UART: 115200 baud
- PWM: D5 and D6
- 74HC595: SHCP D2, STCP D4, enable D7, data D8
- Camera servo: D9
- Ultrasonic sensor: trigger D12, echo D13
- Line sensors: A0, A1, A2
- ESP32 camera definition: AI Thinker / OV2640 with PSRAM

The 74HC595 direction bits are:

| Wheel | Forward | Reverse |
| --- | ---: | ---: |
| Front left | `0x40` | `0x80` |
| Rear left | `0x10` | `0x20` |
| Front right | `0x04` | `0x02` |
| Rear right | `0x08` | `0x01` |

The board documentation does not identify which motors share D5 and D6. A
low-power calibration will determine that before closed-loop mixing is enabled.

## Pocket Wi-Fi test

Put the Pocket's internal ExpressLRS module in Wi-Fi mode and connect the Mac
to a routed local network. The monitor first resolves `elrs_tx.local`, then
falls back to the ELRS broadcast, activates a 100 Hz eight-channel stream, and
prints channel values. Resolving the hostname also works when the transmitter
and Mac are in different routed subnets, where broadcasts do not cross:

```sh
cargo run -p elrs-monitor
```

If discovery is unavailable, pass the module IP explicitly:

```sh
cargo run -p elrs-monitor -- 10.0.0.1
```

Motor power must be disconnected or wheels removed during flashing and initial
calibration.

## ESP32-S3 Rust firmware

The ESP32-S3 uses Espressif's Xtensa Rust toolchain and ESP-IDF. The local
toolchain export generated by `espup` is intentionally ignored by Git. Build
the firmware without touching the board with:

```sh
export PATH="/opt/homebrew/opt/rustup/bin:$HOME/.cargo/bin:$PATH"
. .esp/export-esp.sh
cd firmware/esp32-controller
cargo build --release
```

The controller is a YD-ESP32-S3 with an ESP32-S3-WROOM-1-N16R8 module: 16 MB
flash and 8 MB octal PSRAM. GPIO17 (TX) and GPIO18 (RX) are reserved for the
Arduino link. Native USB remains available for flashing and diagnostics.
Factory flash backups remain under the ignored `backups/factory/` directory.

## OTA foundation

The OTA memory map has two 4 MiB ESP32-S3 application slots, a 64 KiB staging
partition for an Arduino image, and automatic ESP32 rollback. Validate the map
without touching the board:

```sh
cd firmware/esp32-controller
espflash partition-table partitions.csv
```

The first installation is necessarily over USB because it replaces the
factory bootloader/partition layout. It must use `partitions.csv`, target
`ota_0`, and the rollback-enabled bootloader produced by the build. Do not run
this until intentionally replacing the backed-up factory firmware:

```sh
espflash flash \
  --partition-table partitions.csv \
  --target-app-partition ota_0 \
  --bootloader target/xtensa-esp32s3-espidf/release/bootloader.bin \
  target/xtensa-esp32s3-espidf/release/esp32-controller
```

Subsequent ESP32 OTA uploads use a plain application image, generated without
merging the whole 4 MiB flash:

```sh
espflash save-image \
  --chip esp32s3 --flash-mode dio --flash-freq 80mhz --flash-size 16mb \
  --partition-table partitions.csv --target-app-partition ota_0 \
  target/xtensa-esp32s3-espidf/release/esp32-controller wobot-esp32s3.bin
```

Updating the Arduino through the ESP32 requires one extra reset signal. The
safe transistor circuit and the complete update protocol are documented in
[`docs/ota-design.md`](docs/ota-design.md).

### First Wi-Fi setup

On first boot, or whenever the saved network cannot be reached, the ESP32
creates this temporary configuration network:

```text
SSID:     Wobot-Setup
password: wobot-update
panel:    http://192.168.71.1
```

The panel scans nearby 2.4 GHz networks, accepts a hidden SSID as well, and
stores the selected SSID and password in NVS. After restarting, Wobot joins the
configured LAN and advertises the maintenance panel as
`http://wobot.local`. The OTA page includes an explicit action for erasing the
credentials and returning to setup mode.
